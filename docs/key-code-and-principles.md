# 关键代码与实现原理

## 浏览器端分工

HTML 由 Vue 单文件组件的模板生成；CSS 分在 `styles/tokens.css`、`app.css`、页面样式文件中，主题 token 用 CSS 变量统一管理；TypeScript 为页面状态、API 数据和编辑器扩展提供类型。Vue 负责组合页面与响应式交互，Tiptap/ProseMirror 负责富文本文档模型。

## 富文本与媒体

编辑器保存 ProseMirror JSON，而不是直接保存任意 HTML。段落、标题、列表和图片节点组成正文树；API 服务端清洗节点和 mark，只接受已支持的格式、受限链接和自有媒体 ID。正文渲染为编辑器、只读分享视图或导出 HTML。媒体文件在数据库仅保留元数据，原始文件由私有文件目录保存；用户阅读和分享图片走各自有权限的 API 路径。

图片可通过文件选择、批量选择、拖放和粘贴插入。上传记录保存所有者、格式、尺寸和哈希。待上传 Blob 保存在 IndexedDB，联网后先传图片，再把服务端媒体 ID 写入日记。图片节点保留说明、显示宽度、居中裁剪与旋转信息。分享和导出根据这些信息生成展示图。

## 自动保存、离线与冲突

写作页按账号 ID 保存本地编辑内容，防抖后请求服务端保存。操作 ID 记录在 `journal_save_operations` 中。重发相同操作不会再次创建或更新。服务端根据日记版本识别冲突并返回当前版本，用户可以从服务器载入或保留本地版本为副本。清空时保存最后有效正文和待删除标记，站内离开后将最后有效内容移入回收站。Service Worker 按构建清单缓存应用资源，IndexedDB 单独缓存用户内容。

## Java、MyBatis 与 MySQL 数据链路

Vue 调用 `lib/api.ts`；Spring Controller 读取已认证用户；Service 在事务内检查所有权、状态、版本和业务规则；MyBatis Mapper 对用户 ID 与资源 ID 同时加条件；MySQL 通过 Flyway 管理结构演进。媒体二进制文件与关系数据分开持久化，`media_assets` 记录引用元数据。

写请求使用服务端会话 Cookie 和 CSRF Token。密码由 BCrypt 保存，邮箱令牌以散列值和过期时间存储。CSRF、所有者范围及会话配置在正式部署前仍要在真实浏览器与数据库组合下做安全验收。

## 分享申请快照与审批

申请分享时服务端固定当前日记内容快照。普通编辑只更新私人日记，不改变待审/已批准快照。管理员审核快照本身；批准后切换分享链接当前版本指针。这样较新的私人编辑不会通过旧链接泄露。撤销、过期、删除与同时审核的完整竞态场景列在 A20–A27，尚未全部集成验收。

## 写作活动与日期覆盖

写作活动按日记和实际写作日期去重。离线队列保留编辑时的当地日期，账号时区变化对后续记录生效。日期覆盖由当前有效日记的所属日期计算。补写旧日记会同时增加今天的写作活动和旧日期的日记覆盖。仅调整日期、日记本或标签时，写作活动保持原值。

## Markdown 导入与导出

导入页读取 Markdown 或图文 ZIP，从各级日期标题拆分记录并保留普通标题和代码块。Windows 路径转换为 ZIP 内路径后校验边界。预览允许补年份、改日期和选择只导入文字。服务端根据内容和媒体哈希识别重复条目，并以成功导入批次为单位记录活动。

阅读版导出将处理后的图片内嵌在 HTML 中。打印路径等待图片解码和字体可用后调用浏览器打印。压缩档使用最长边 1400 像素的 WebP。带变换的动画 GIF 在导出和分享中使用静态画面。

备份格式 V2 记录来源档案 ID、对象身份、媒体 SHA-256、清单、关系和时间信息。追加恢复按稳定身份识别重复记录和活动，内容冲突保存为副本。V1 可以恢复，旧版聚合活动按来源用户名、日期和序号构造身份。单份备份的媒体上限为 105 MiB，恢复页接受不超过 150 MB 的 JSON。可选偏好包括昵称、主题、时区和提醒日程。

## 回收站和媒体引用

回收站按删除时间加 15 × 24 小时计算到期。服务端先校验期限，后台再清理到期记录。原本子已删除时恢复到默认本子。清理媒体前检查保留中的日记、分享快照、日记本封面和标签图标引用。注销则立即移除账号并撤销会话，文件占用时根据持久任务重试。

## 历史上的今天

`WorldHistory.vue` 按账号时区从前端内置资料取出当天的世界事件，并显示原始修订链接。写作页显示预览，回顾页显示完整条目。`RecordsView.vue` 通过当前用户的日记接口查询历年同月同日记录，传入上一年 12 月 31 日作为日期上限。私人查询即使失败，公开事件仍可阅读。

## 邮件与 Web Push

`ReminderJob` 根据用户时区和星期设置检查到期提醒。发送前检查服务端的写作活动，并用账号、当地日期和渠道的唯一约束防止重复投递。`WebPushService` 生成 VAPID 签名并加密通知，Service Worker 接到推送后显示通知。邮件和推送只包含通用提醒文案。配置步骤见 [部署说明](deployment.md)。
