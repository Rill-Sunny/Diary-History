## 3. 已确定的技术路线

必须采用：
- 前端：Vue 3、TypeScript、Vite。
- 页面基础：语义化 HTML 模板和真实 CSS 样式。
- 编辑器：Tiptap 开源核心，配合必要的免费开源扩展或自定义扩展。
- 后端：Java、Spring Boot。
- 数据访问：MyBatis。
- 数据库：用户已有的 MySQL。
- 数据库迁移：Flyway。
- 身份认证与权限：Spring Security。
- 图片：服务器持久目录保存文件，MySQL 保存归属、引用和编辑信息。
- 离线：浏览器本地持久存储及待同步队列。
- 提醒：后台调度、邮件、Web Push。

实施前核对相互兼容的稳定版本，并锁定依赖；记录实际采用版本。不要虚构用户本机的 JDK、MySQL、Node 或其他软件版本。

HTML/CSS 应当能在项目中清楚检查：
- Vue 单文件组件使用实际 HTML 结构。
- 使用 CSS 文件或组件样式实现布局、正文排版、主题变量、响应式、焦点状态和动效。
- TypeScript 用于交互和业务逻辑，构建后输出浏览器可运行的 JavaScript。
- 技术说明明确说明 HTML、CSS、Vue、TypeScript 各自的作用，并指向实际源码。

核心编辑、图片、离线、导入导出和备份能力不能依赖付费编辑器扩展、商业转换服务或试用期。逐项检查实际依赖包的许可。Tiptap 核心开源，不代表其所有云服务、模板和扩展均免费。

采用适合本项目规模的单个 Java 后端服务。MySQL 是真实服务端持久存储；浏览器存储仅承担离线内容和缓存，不能以本地假数据或模拟 API 替代生产数据链路。

使用本项目独立的新数据库、测试数据库和媒体目录。Flyway 只管理本项目范围，不清空、覆盖或重建用户其他已有数据库。

## 5. 页面和信息结构

按以下功能区域组织。可以采用独立页面、侧栏、抽屉和弹窗组合；桌面与手机分别安排。

- 写日记：首页，打开今天最近编辑的一篇；提供“再写一篇”。
- 全部日记：标题和正文搜索，日期范围、日记本、标签组合筛选，阅读和编辑入口。
- 日记本与标签：日记本、封面、标签样式库、私人图标及审核状态。
- 日历与写作记录：日记日期覆盖、写作活动热力图、连续天数和统计。
- 历史上的今天：历年同日私人日记、全球历史事件灵感。
- 分享管理：主动提交审核、审核状态、有效期、链接和撤销。
- 回收站：恢复、彻底删除、剩余保留天数。
- 数据管理：Markdown 导入、PDF/HTML 导出、完整备份与追加恢复。
- 设置：账号资料、时区、提醒、主题与主题色、注销。
- 管理员审核：标签图标审核、日记分享版本审核。
- 分享阅读页：登录与链接有效性检查、只读内容。

搜索必须能处理中文文本；按标题与正文检索，明确组合筛选语义。搜索结果不能混入其他账号的数据。回收站、私人日记与分享读者的可见范围分开。

## 6. 账号、身份与权限

### 6.1 注册登录

开放多用户注册，各账号拥有独立私人空间。
- 注册使用邮箱和密码，并设置唯一用户名。
- 登录同时支持邮箱＋密码、用户名＋密码。
- 注册验证邮箱归属。
- 支持忘记密码、邮件重置、修改密码。
- 支持修改昵称、头像和邮箱；修改邮箱验证新邮箱。
- 支持电脑与手机同时登录。
- 登录标识、用户名、昵称分别建模，明确唯一性和规范化规则。
- 密码使用适当的密码哈希；验证和重置令牌有有效期、单次使用与必要限流。
- 会话实现由你选择，但必须支持退出、重置密码和注销时撤销相应会话。

### 6.2 权限边界

普通用户只能管理自己的日记、日记本、标签、媒体、统计、提醒、导出和备份。

默认私密不是仅在前端隐藏入口。所有后端查询、修改、媒体读取、导入导出和恢复接口都必须校验实际登录身份和数据归属。客户端提交的 ownerId、userId、role 等字段不能授予权限。

管理员权限限于：
- 审核提交的私人标签图标。
- 审核作者主动提交的日记分享版本。
- 查看完成审核所必需的申请信息和处理记录。

管理员不能通过审核接口读取未提交的私人日记、当前未提交的新修改、其他日记、完整备份或未裁剪原图。管理员如拥有自己的日记，仍按普通所有者权限访问自己的内容。

提供明确的管理员初始化方式，避免开放注册直接取得管理员角色。演示账号与正式账号配置区分。

### 6.3 立即注销

注销前验证当前身份并展示影响。用户确认后：
- 立即停用账号并撤销所有服务端会话。
- 撤销全部分享，取消待审申请及待发送提醒。
- 清理该账号的私人数据和不再需要的媒体。
- 不套用日记回收站的 15 天规则。
- 离线设备再次联网时识别账号失效，并处理对应的账号缓存。
- 注销与普通退出登录有明确不同的操作及提示。

## 7. 日记、日期、日记本与标签

### 7.1 日记基本规则

- 一天可以写多篇。
- 可以补写过去的日记，可以修改正文和所属日期。
- 所属日期仅允许用户时区中的今天及以前，后端也要校验。
- 用户可以设置时区，默认 Asia/Shanghai（北京时间）。
- 日记所属日期、创建时间、更新时间、实际写作活动时间分别表达。
- 正文必须有有效可见文字或有效图片。纯图片日记允许；标题、空格、空标签或只有无意义格式不构成有效正文。
- 标题可选，未填写时默认显示所属日期。区分自动日期标题与自定义标题，修改日期时不要覆盖用户自定义标题。
- 不区分“草稿”与“已完成日记”，不增加必须点击“完成”才能保存或打卡的步骤。
- 本地待同步或正在编辑状态不等于新增“草稿”业务状态。
- 首页打开今天最近编辑的有效日记；没有则提供空白编辑器。空白编辑器不能自动制造空日记。
- “再写一篇”开始新的记录；处理当前内容的保存或待删除状态后再切换。

### 7.2 日记本

- 用户可以创建多个日记本。
- 每篇日记属于一个日记本，可以移动。
- 系统提供始终可用的默认日记本。
- 删除日记本时，内部日记一起移入回收站；展示影响范围。
- 恢复日记时原日记本若仍存在，可恢复原归属；原日记本不存在时放入默认日记本。
- 完整备份的正常追加恢复应保留或重建日记本结构，不把所有正常日记都放进默认日记本。

### 7.3 标签

- 每篇日记可拥有多个标签。
- 用户可创建自定义标签。
- 提供颜色、样式和内置图标库，选择操作清楚，深浅主题均可辨识。
- 自定义上传的小图标只供本人使用，不进入公共素材库。
- 自定义图标的审核规则见第 12 节。
- 删除标签只解除关联，不删除日记正文、图片或日记本。
- 标签归属必须隔离，不可通过其他账号的标签 ID 挂接或读取数据。

## 8. 富文本和图片体验

### 8.1 编辑器

至少实现：
- 加粗、斜体、文字颜色。
- 标题层级、引用、链接、分隔线。
- 图片说明。
- 字体、字号调整。
- 工具栏隐藏与显示。
- 适合中文输入法的编辑与撤销重做，不在输入法组合输入时错误保存、拆字或跳光标。

采用有版本的结构化正文和稳定媒体引用，使编辑、阅读、分享、PDF 和 HTML 对相同内容有一致解释。不要直接信任任意 HTML 或脚本。

### 8.2 添加和排列图片

同时支持：
1. 文件选择。
2. 拖入图片文件。
3. 粘贴剪贴板中的图片或截图。
4. 多选并批量插入。

图片可放在相应文字段落之间，也可集中成相册。用户可以：
- 调整顺序。
- 调整显示尺寸，适配阅读容器。
- 添加图片说明。
- 点击查看大图。
- 裁剪和旋转。

“在段落位置插图”描述的是用户操作，不强制采用编辑器技术上的 inline 节点。选择能正确处理排版、说明、移动和导出的实现。

预计普通日记约 0—1 张图，多图日记约 3—4 张；这些是典型场景，不是强制数量上限。设置合理的格式、大小和资源限制，明确显示错误，不能静默丢图或伪装成付费限制。

### 8.3 原始素材与显示效果

- 保存上传原图及必要编辑信息，能够还原图片处理状态。
- “高质量导出”保留当前裁剪、旋转后的效果，并尽量保留质量。
- “压缩导出”在保持相同显示内容的前提下减小体积。
- 阅读版导出不能因为选择高质量，就重新露出已裁掉的部分。
- 完整备份保留原图和编辑信息。
- 分享和审核使用当前提交版本实际展示的图片，不授权访问未经裁剪的原始文件。
- 已审核分享引用的图片版本保持稳定；作者后续替换、裁剪或旋转不能原地改变旧审核版本。

## 9. 自动保存、离线、冲突与清空删除

### 9.1 保存状态

持续进行本地持久保存和合理的服务端自动保存，不只在关闭页面时保存。
明确区分：
- 已在本机保存。
- 待同步或同步中。
- 已同步到服务器。
- 保存失败或空间不足。
- 存在冲突，需要处理。

本机保存成功不能显示成服务器已持久化。失败时保留可恢复内容，并允许重试。

### 9.2 离线范围

已访问并具备所需缓存的应用在断网时可以：
- 新建日记。
- 编辑已打开的日记。
- 插入本地图片，随内容保存在本机，联网后上传。
- 浏览此前已在本机加载的日记。

已持久保存的内容应能在意外关闭后恢复。浏览器重新打开时，如果本机已有应用壳和所需缓存，应恢复可用的离线编辑现场。未缓存的内容明确提示不可离线访问。

离线缓存按账号隔离。账号切换不能显示另一人的日记。普通退出不能悄悄丢弃尚未同步的内容，应提供清楚的处理方式。注销后的缓存失效与普通退出分开处理。

### 9.3 同步与冲突

- 使用持久化的操作身份、版本或等效机制处理重试及乱序。
- 同一离线新建操作重复上传不能产生多篇日记。
- 图片上传失败、网络断开后能继续同步，不能只剩文字或失效的临时图片地址。
- 两个设备对同一篇产生不兼容修改时，保留双方内容，提示选择或手动整理，不静默采用最后写入覆盖。
- 编辑与删除、恢复、账号注销等并发情况也要保护用户内容，不用迟到的操作复活或覆盖错误对象。
- 冲突副本自动生成本身不制造虚假的额外写作活动。

### 9.4 全部清空后的删除

- 只有文字、图片等有效正文全部消失时，才进入“待删除”的编辑状态。
- 清空后仍停留在当前编辑页：不立即删除，也不以空正文覆盖最后有效内容。
- 清空后重新输入有效文字或图片：取消待删除状态。
- 清空后正常站内切换到其他日记、再写一篇、返回列表或离开编辑功能：移入回收站。
- 回收站保留清空前最后有效内容、图片和排版，可以完整恢复。
- 刷新、误关标签页、崩溃等情况保留恢复线索，再次进入时清楚提示处理，不只依赖关闭事件执行删除。
- 新建空白页从未输入有效内容便离开：不生成日记、回收站条目或打卡。

## 10. 两类统计与连续天数

### 10.1 写作活动

按实际写作日期记录活动：
- 同一篇日记，同一用户自然日有效修改多次，最多贡献 1 次。
- 同一天有效修改不同日记，按不同日记数增加热力值。
- 第二天再次有效修改同一篇，可贡献第二天的 1 次。
- 标题、正文、图片和文章排版的实际修改计入。
- 单纯修改标签、日记本、所属日期不计入。
- 纯浏览、无变化保存、保存重试、同步重试不计入。
- 批量 Markdown 导入成功一次，仅给实际导入当天增加 1 次，不按导入篇数增加。
- 完全重复、全部跳过或没有成功导入条目的操作不制造新活动。
- 删除或彻底删除日记不撤销历史写作活动。
- 恢复回收站、恢复完整备份、审批分享、自动生成冲突副本本身不增加写作活动。
- 完整备份中的历史活动去重合并，不直接累加计数。
- 离线活动同步后保留其原始实际写作日期，不改记为联网同步日期。

“今天”、日界线和连续天数按用户时区处理，默认北京时间。合理默认：时区变化对后续活动生效，不悄悄改写已经记录的活动日期；在文档中说明具体实现。

提供类似提交记录的热力图、当日活动数、当前连续天数和历史最长连续天数。颜色深浅反映活动多少，并有日期和数量说明。明确“今天尚未写但昨天写过”的连续天数展示口径，避免每天凌晨立即造成误导。

### 10.2 日记日期覆盖

按当前未删除日记的所属日期显示：
- 今天补写上周：写作活动发生在今天，日记覆盖发生在上周。
- 修改所属日期：覆盖位置随之变化。
- 删除日记：覆盖按剩余有效日记重新计算。
- 导入旧日记：按其历史所属日期显示覆盖。
- 同一天多篇能查看对应篇数和日记。

写作活动与日期覆盖必须分别命名和解释。删除不撤销的是历史写作活动，不是要求已不存在的日记仍被计入当前日期覆盖。

## 11. 分享与日记内容审核

### 11.1 基本边界

- 普通日记默认私密，创建、编辑、自动保存、离线同步都不需要管理员审核。
- 只有作者主动提出分享申请，才提交一个确定的内容版本。
- 该版本的文字与图片由管理员审核。
- 首次审核通过前不生成可访问的分享链接。
- 分享链接的接收者必须登录本应用。
- 任何已登录用户持有有效链接即可阅读，不要求作者指定账号名单。
- 作者可设置有效期、随时撤销。
- 日记删除后分享立即失效，恢复日记不会恢复旧链接。
- 账号注销、链接撤销或到期后，后续审核操作不能使其复活。

### 11.2 三种内容身份

明确区分并独立保存：
1. 作者当前私人内容。
2. 作者主动提交、等待审核的固定版本。
3. 分享链接当前展示的已审核版本。

示例：
- V1 已审核并分享。
- 作者修改为 V2：读者刷新仍看到 V1。
- 作者主动提交 V2 后继续私人编辑成 V3：管理员审核的是 V2，不能顺带查看或批准 V3。
- V2 通过：读者刷新看到 V2，V3 仍然私密。

这属于分享版本管理，不等于新增面向用户的通用日记历史版本功能。

### 11.3 重新审核

- 修改后由作者主动点击提交新版审核。
- 不因每次自动保存而创建审核任务。
- 旧已审核版本在等待期间继续可见。
- 新版审核通过后原有效链接切换到新版。
- 拒绝新版不删除私人内容，旧已审核版仍按有效期可见。
- 审核版本包含所有将公开的内容：标题、正文、日记日期、图片、图片说明及影响展示的排版。
- 不默认公开私人日记本、私人标签、邮箱或其他不必要资料。
- 如展示作者信息，也要明确其公开范围，避免动态读取私人资料绕过审核。
- 图片、裁剪结果及相关资源与审核版本绑定，不能通过原地修改文件绕过审核。
- 较旧申请晚于较新申请获批时，不能使分享内容回退。
- 重审不自动延长原有效期。
- 生效、撤销、过期、删除与审批并发时要重新核对状态，防止失效链接复活。

接收者刷新获取最新已发布审核版本即可，不要求在打开页面期间自动实时更新。

### 11.4 只读与下载限制

- 分享页不提供整篇导出、备份或图片下载入口。
- 后端禁止分享接收者调用作者的 PDF、HTML、备份、原图下载接口。
- 不能通过媒体地址、日记 ID、版本 ID读取私人最新版、未审版本或其他用户资源。
- 用于显示已审核图片的读取权限仅覆盖本次有效分享需要的处理后图片。
- 不承诺技术上绝对禁止复制、截图或浏览器留存已展示内容。
- 作者先自行导出 PDF，再通过其他方式分享文件，不需要接收者登录本应用。

## 12. 私人标签图标审核

这是独立于日记分享审核的流程：
- 系统检查格式、大小和真实文件内容等基本条件。
- 管理员审核图标具体内容是否违规。
- 通过前不能使用，界面可用内置图标占位。
- 通过后仅上传者本人可用。
- 管理员看到图标、必要提交者标识、提交时间和状态，不获得相关私人日记的阅读权限。
- 拒绝时提供原因，允许用户重新上传。
- 替换已批准图标时，新图重新审核；期间继续使用旧的已批准图标。
- 恢复到新环境的自定义图标重新审核，不能信任备份里自称“已批准”的字段。
- 非法格式、过大文件或解析失败给出可理解错误。
- 不将图标审核扩展成所有私人日记图片都必须审核。

## 13. 历史上的今天

页面名称统一为“历史上的今天”，内部清楚区分：

### 13.1 我的往年今日

按用户时区的当前月日，展示历年同一天的未删除私人日记。按年份、标题、摘要或配图组织，可进入阅读。仅本人可见。

### 13.2 世界历史上的今天

- 展示该月日发生过的全球综合历史事件，为写作提供灵感。
- 仅功能用途参考“倒数日 · Days Matter”，界面继续使用本项目 Craft 风格。
- 展示事件年份、简要说明及可追溯来源。
- 选择可用、许可明确的数据源，记录来源与获取方式，提供缓存和失败处理。
- 不向历史事件服务发送用户日记正文。
- 不为填满页面而编造事件。
- 来源不可用时显示已有适用缓存或真实空状态，不能把其他日期的数据当作今天。
- 用户主动点击后才可把相关内容作为引用或写作灵感，不自动写入日记。
- 展示数量、展开方式、排序等由你合理设计，兼顾写作时的安静体验。

## 14. 提醒

- 用户可以选择邮件、浏览器/系统通知，二者可以同时开启，也可分别或全部关闭。
- 用户设置提醒时间，可选每天、工作日或一周中的指定几天。
- 合理默认：工作日表示周一至周五，界面清楚说明，不隐含节假日调休推断。
- 按用户时区安排提醒。
- 当天已有服务端已同步的写作活动后，跳过当天尚未发送的催写提醒。
- 后台无法知道尚未同步的离线活动；同步后正确去重，不把这一限制包装成已解决。
- 通知内容不包含私人日记正文。

必须满足关闭网页后的提醒需求：
- 邮件由后台计划任务发送。
- 浏览器通知采用真实 Web Push/Service Worker 能力，不能用页面内定时器冒充。
- 支持环境中，完成授权且网络、系统通知可用时，关闭网页仍可接收。
- iPhone/iPad 提供符合平台要求的添加到主屏幕和启用通知引导。
- 不支持、未授权、取消订阅、服务未配置和发送失败，显示真实状态。
- 用户未开启邮件时，不能因浏览器通知不可用而擅自开启邮件。
- 不承诺断网、设备关机、系统限制或所有浏览器完全退出情况下准点必达。
- 后台任务、重试和服务重启具有必要去重，避免反复催写。
- 账号注销后取消相关计划和订阅。

## 15. Markdown 导入

### 15.1 已知输入结构

用户的一个 Markdown 文件包含多天日记，图片采用 Windows 相对路径，没有现成标签。示例只保留结构，正文必须采用虚构内容：

    # 10.30

    第一篇示例文字。

    ##### 10.31

    第二篇示例文字。

    ![示例图片](..\日记素材\配图\example.jpg)

实际文件可能使用不同级别的日期标题。不能只支持五级标题。

### 15.2 日期识别和拆分

- 按 Markdown 结构扫描各级标题；可解析的日期标题才是候选分隔。
- 不能把每一个标题都当作新日记。
- 非日期标题保留为正文及其原有层级。
- 代码块、引用示例等内部出现类似日期的文本，不能被简单逐行正则误拆。
- 日期识别保持保守，章节数字或句子里偶然出现日期片段不能直接拆分。
- 无年份时由用户在导入界面选择默认年份，不擅自以当前年份或文件修改年份替代。
- 预览显示每篇完整日期、标题、目标日记本和内容摘要，允许修改。
- 可能跨年的位置提示确认，不因日期变小就自动增加年份。
- 无效日期、未来日期、无法归属的段落或首个日期标题之前的文字进入待处理流程，不静默丢弃。
- 标题识别以实际文件内容为准，不将聊天粘贴产生的转义当作原始文件语法。

### 15.3 图片和输入包

- 支持纯文字 .md 导入。
- 带图时支持 .md 与相应目录打包的 ZIP，保留相对路径关系。
- 规范化 Windows 反斜杠与中文路径，映射到用户实际提供的图片。
- 允许在上传包内部解析合理的相对目录关系，但不能越出上传包范围读取服务器文件。
- 不因为路径包含“..”就访问服务器上的同名目录。
- 缺图时列出具体条目和引用，允许用户修复，或明确选择只导入文字。
- 只有缺失图片且没有有效正文的条目不能假装导入为有效纯图日记。
- 文件解析、压缩包展开、上传大小及资源耗用具有合理限制。

### 15.4 预览、确认和去重

- 导入前展示将产生的篇数、日期、归属、异常、缺图和重复数量。
- 用户确认后写入。
- 完全重复默认跳过，显示原因，不覆盖现有日记。
- 无法确定是否相同的内容可提示或保留新副本，不静默覆盖。
- 导入任务和重试具有稳定身份，避免重复插入。
- 一次有实际新增内容的批量导入，仅给实际执行导入的当天增加 1 次写作活动；日记日期覆盖则按各篇日记在导入预览中确认的所属日期分别计算，不按执行导入的当天计算。

## 16. 作者阅读版导出

提供 PDF 和可离线阅读的 HTML，由作者选择。

导出范围包括：
- 手动选择单篇。
- 手动选择多篇。
- 某个日期范围。
- 某个日记本。
- 需要全部时可选全部日记。

要求：
- 仅导出本人实际选中的内容。
- 明确排序和篇目边界。
- 保留日期、标题、正文排版、图片、图片说明、裁剪和旋转效果。
- 图片质量可选高质量或压缩。
- PDF 合理分页，中文字体可读，避免图片、说明、段落被异常裁切。
- HTML 包含所需图片与必要资源，离线、未登录时仍可完整打开，不依赖应用在线媒体 URL。
- 编辑器、阅读页、PDF、HTML 对正文结构和自定义图片/相册节点采用一致的渲染规则；允许合理分页差异。
- 导出资源应完成加载，不能生成缺图文件却报告成功。
- 不把隐私标签、未选日记、隐藏原图或其他账号资源混入结果。
- 分享接收者没有作者导出权限。

## 17. 完整备份与追加恢复

### 17.1 备份内容

备份当前账号的：
- 日记正文及排版。
- 原始日期、标题、创建/修改等必要时间信息及日记本关系。
- 日记本信息和封面等必要素材。
- 标签、样式及自定义图标资料。
- 图片原文件、处理结果或足以恢复的编辑信息。
- 必要个人设置。
- 写作活动和打卡记录。
- 回收站条目及原删除时间。

个人设置指用户偏好，不将账号密码、会话令牌、邮件服务密钥等当作可迁移偏好。导入文件的身份、管理员角色和审核标志不能直接取得权限。

使用带格式版本、稳定对象身份、清单和必要完整性检查的信息组织备份。写清格式和兼容策略，使备份可实际恢复。

### 17.2 追加恢复

- 默认追加，不清空当前账号。
- 完全相同的记录跳过。
- 同一逻辑日记内容不同，保留副本并标记冲突。
- 重复恢复同一备份不能重复增加日记、媒体和打卡。
- 同名日记本在预览中允许选择合并或另建。
- 同名但样式不同的标签保留差异并提示，不直接覆盖当前样式。
- 默认保留当前个人设置，允许勾选使用备份中的设置。
- 历史写作活动按稳定身份去重合并，恢复动作本身不打卡。
- 恢复前预览新增、重复、冲突、回收站、过期跳过等数量。
- 正常条目保留或重建应有的日记本结构。
- 备份中的回收站条目恢复后仍在回收站，不转为正常日记。
- 自定义图标按既定要求重审，不能绕过审核。
- 不恢复旧分享令牌或使历史失效链接重新生效。
- 恢复只作用于当前用户，不能根据备份的源用户 ID写入其他账号。

### 17.3 回收站期限

恢复备份时保留原删除时间：
- 尚未到期：只保留剩余时间。
- 已超过 15 天：默认不恢复，并在预览和结果中列明。
- 不能将恢复时间作为新的删除时间。
- 跳过一个过期备份条目，不得删除或覆盖本机已有正常日记。

对大备份、坏文件、缺媒体和中途失败提供清楚处理。避免一半数据入库、一半关系断裂；采用可恢复的导入任务或合适的事务分段，并说明策略。

## 18. 回收站与媒体生命周期

- 日记进入回收站后保留 15 天，到期默认彻底删除。
- 页面以清楚但次要的小字显示距离自动删除的剩余天数；同时可显示具体到期时间。
- 明确采用的期限计算口径；推荐删除时间加 15×24 小时，倒计时按剩余时间计算。
- 支持到期前主动恢复和手动彻底删除。
- 删除日记本会使其内部日记进入回收站。
- 原日记本不存在时，恢复到默认日记本。
- 删除日记立即撤销关联分享；恢复后旧链接仍失效。
- 到期检查既要有后台清理任务，也要避免因任务延迟让过期条目仍可正常恢复。
- 清理正文、相关审核快照及无有效引用媒体时核对引用关系。
- 回收站中尚可恢复的内容、有效审核分享版本、仍有合法引用的图片不能被提前清理。
- 删除不撤销写作活动；保留活动统计不需要继续保留被彻底删除的私人正文。

## 19. 后端、数据结构和接口设计要求

根据上述业务设计实际表、索引、约束、事务和接口，不要求照搬固定表名。

至少覆盖：
- 用户、身份验证、会话或可撤销认证状态。
- 用户设置与时区。
- 日记、正文版本或编辑并发版本。
- 日记本、标签、关联关系、封面。
- 媒体、图片处理信息、媒体引用与所有权。
- 写作活动及必要去重身份。
- 图标申请与审核记录。
- 分享申请快照、审核状态、公开版本指针、分享令牌与失效状态。
- 导入、导出或恢复任务及结果。
- 提醒设置、推送订阅、发送记录。
- 回收站时间与清理状态。

要求：
1. 数据采用适合中文和表情的编码。
2. 日期、时间戳和时区职责清楚，服务端逻辑可使用可注入时钟进行测试。
3. API 的校验、状态码和错误结构一致。
4. 并发修改、审批、撤销、删除与恢复使用必要事务或版本比较。
5. 核心去重必须持久有效，不能只靠前端防抖。
6. 富文本、导入 HTML、链接和文件处理防止脚本注入及越权访问。
7. 上传核对真实格式，不信任文件名和客户端 MIME；文件名、路径和压缩包处理不能越界。
8. 日记图片及审核资源通过受控访问获得，不暴露一个无需鉴权即可浏览的私人媒体目录。
9. 日志记录请求、任务和错误所需信息，不记录密码、令牌、私人日记全文或完整图片数据。
10. 必要配置通过环境变量或明确的配置文件提供，敏感值不进入仓库。
11. 备份、删除、媒体清理与审核版本的引用要一致。
12. 说明实际权限模型、并发控制和恢复策略，避免代码与文档各说一套。
